# GovAgent-Shield AI Coding Instructions


## 项目介绍

本项目为政务智能Agent安全防护系统。

核心目标：

通过输入检测、权限控制、风险评估、诱饵监控、行为分析等模块，
防止Agent产生：

- Prompt Injection
- 越权访问
- 敏感数据泄露
- 工具调用滥用
- 知识库投毒
- 诱饵文件触碰


# 修改代码原则


## 1. 不破坏已有功能

修改任何模块前：

必须：

1. 阅读当前代码
2. 理解调用关系
3. 保留已有接口


禁止：

- 随意删除函数
- 改变已有API格式
- 删除测试



# 2. 优先修复逻辑，而不是修改测试


如果测试失败：

必须：

第一步：
分析失败原因

第二步：
判断：

- 测试错误？
- 代码错误？
- 设计冲突？


第三步：

优先修改代码。


禁止：

为了通过测试：

- 删除测试
- 降低测试标准
- 修改预期结果


---

# 3. Agent安全优先


本项目不是普通聊天机器人。

任何涉及：

- 文件读取
- 数据查询
- 数据上传
- 工具调用

必须经过：

用户输入检测
        ↓
Agent Planner
        ↓
PermissionChecker
        ↓
Risk Engine
        ↓
Tool Gateway


禁止绕过安全模块。


---

# 4. 工具调用规则


所有工具调用必须经过 ToolCall。


格式：

ToolCall:

{
 tool_name,
 parameters,
 reasoning
}


禁止：

Agent直接执行工具。


---

# 5. 风险评分规则


风险来源包括：

R_input:
输入风险

R_tool:
工具风险

R_behavior:
行为风险

R_output:
输出风险

R_decoy:
诱饵触碰风险


新增风险规则：

必须说明：

- 风险来源
- 判断依据
- 影响模块


---

# 6. Red Team测试规则


攻击样本位于：

samples/red_team/


用于：

验证系统防御能力。


修改安全模块后：

必须运行：

pytest tests/


并记录：

- 通过数量
- 失败原因
- 修复方案


---

# 7. 修改代码流程


任何代码修改：

必须：

1. 查看相关文件
2. 分析问题
3. 提出修改方案
4. 修改代码
5. 运行测试
6. 汇报结果


不要直接大范围重构。

## 修改原则

遇到测试失败：

禁止：
- 删除关键词解决冲突
- 降低检测范围
- 修改测试要求

优先：
- 调整意图优先级
- 增加上下文判断
- 增加风险权重
- 优化匹配策略


# Language Rule

所有解释、分析、修改计划必须使用中文。

代码中的：
- 类名
- 函数名
- 变量名

保持英文。
